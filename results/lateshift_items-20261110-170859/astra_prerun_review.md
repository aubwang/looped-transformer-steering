## Optional / interpretation and follow-up

4. **The per-family decision rule matches section 6, but it is a screening heuristic.** `huginn_addition/analyze_lateshift.py:12`; `docs/lateshift_screen.md:118`.
   Inclusive usability bounds, change thresholds, flicker ratio, and confirmation Wilson calculation agree (the 1e-15 boundary tolerance is harmless). At n=64, BORDERLINE means 7–9 changes and QUALIFIES means at least 10; seven changes permit at most two 31→32 changes. A true 10% family clears the change screen only 46.1% of the time, versus 86.4% at 15%, before usability/flicker exclusions. Thus a negative screen is a budget-driven stopping decision, not strong evidence against every 10% family.
   The chance values are reasonable candidate-guessing baselines, not guarantees against shortcuts. For example, the built count set has answer 3 on 18/64 items (28.1%), above its 26.7% usability floor without counting. A biased near-chance system with transient early noise can therefore pass the screen. Stationary frequent flicker is discouraged, but noise that decays before loop 31 passes; wrong→wrong shifts also count. A binary family needs at least 39/64 correct; valid binary flips imply correctness transitions, but can cancel with no net gain. L32 accuracy .60, D .05, change .20 correctly yields CHANGES BUT UNUSABLE for this matched-pair purpose; it does not establish that L32 is settled. D above .90 is likewise excluded deliberately.
   **Recommendation:** retain the preregistered thresholds, label conclusions as operational eligibility for this pair, and inspect the already-reported margins, correctness transitions and 32→33 changes before interpreting shifts as useful computation. No threshold alone proves serial reasoning.

5. **Confirmation helps selection bias but is not a familywise guarantee.** `docs/lateshift_screen.md:125`; `huginn_addition/analyze_lateshift.py:16`, `:60`.
   At n=300, 30 changes already give Wilson lower bound .07095, so the interval requirement adds no stricter count threshold than c≥.10.    Also `--confirm` rejects the supplied canonical master JSON because it contains i<80, even when the NPZ contains only fresh observations; missing `i` defaults to 80 and passes.

Before confirmation, validate explicit indices on the actual paired collected items and require i≥80; alternatively save and supply a filtered i=80..379 manifest. 7. **The search is reasonable, but several families permit shallow shortcuts.** `docs/lateshift_screen.md:40`; `huginn_addition/lateshift_app.py:213`, `:247`.
   Dependency assignments, pointer composition, accumulators and shuffled dependencies are sensible serial-computation probes. Addition can be parallelized, Boolean trees often short-circuit, repeated swaps can cancel, and ARC often measures knowledge. These controls still help locate eligible tasks; one-token output and 1B capacity constrain the search.
   **Recommendation:** optional substitution, not additional budget: deepen ptr3 to five pointer applications using the same eight mapping lines and two demonstrations. This adds almost no prompt cost and targets dependency depth more directly than more arithmetic variants. It is not clearly worth changing a fixed screen now; keep it as a next-design suggestion.
